### Bug Fixes

* On Windows, `set-value` and `clear` on a classic Win32 edit, or on a combo box that has an edit, now replace the text the way typing does (`EM_SETSEL` then `EM_REPLACESEL`, step `EditControl.ReplaceSel`), so the application is told the text changed. `ValuePattern.SetValue` arrives as `WM_SETTEXT`, which a multiline edit and a combo box's edit never report to their owner: the Windows 11 Save as dialog's File name field read back the written path while Save wrote the dialog's suggested name. On the hosted windows-11-arm runner the Store Notepad save recipe now saves to the written path 7 of 7 runs, against 0 of 7 before, and a WinForms multiline `TextBox` and editable `ComboBox` now raise `TextChanged`. Read-only and disabled edits, drop-down lists, values over the edit's text limit or holding U+0000, and every other control keep `ValuePattern.SetValue`. ([#218](https://github.com/gshost1/agent-desktop/pull/218))
