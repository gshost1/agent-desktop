### Bug Fixes

* `find --first --name` returns the first match whose whole name equals `--name`, and the first match only when none does, as the full match list already ordered them. It returned the first match in traversal order, so after a Subscript command `find --surface menubar --name Subscript --first` returned TextEdit's `Undo Subscript` and an agent that acted on it undid its own format. On macOS a match outside list and table rows still comes before any inside them, so `--first` reads no more of the app than before. A read that runs out of budget no longer settles `--first` on a match whose name only contains `--name` while part of the tree outside the rows is unread: find returns `TIMEOUT`, or with `--allow-partial` that match with `complete: false`. `--last` and `--nth` keep traversal order, and the C find entry point is unchanged.
