### Performance

* `snapshot`, `find` and every other command that saves a snapshot no longer sync `refmap.json` and `latest_snapshot_id` to disk on Linux and macOS, which removes the 4 fsyncs every save issued (68-86 ms per command on a loaded Linux ext4 laptop, about 18 ms idle; `snapshot -i` on GNOME Text Editor went from a 135 ms to a 78 ms minimum). Both files are still written to a temporary and renamed into place, so a killed process leaves the old file or the new one whole. After a power loss or kernel crash, a ref map or pointer that is missing, empty, cut short or unparsable now reads as a missing snapshot (`SNAPSHOT_NOT_FOUND`, retry safe after a new snapshot) instead of `INTERNAL`. Windows, session manifests, agent profiles and trace files keep their flushes. ([#NNN](https://github.com/gshost1/agent-desktop/pull/NNN))
