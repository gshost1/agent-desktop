### Performance

* `find --text` with `--first`, `--last` or `--nth` reads actions and states only at the window root, not on every node. A root match is still published from the one window read, and a deeper match is re-read over its own subtree, the same check as before. `--has` and `--has-not` without `--text` read as before. On platforms that read only the requested fields (macOS), each `wait --text` poll after the first reads names, values and descriptions alone, and builds the snapshot only when that read cannot rule the text out. Measured on Linux: equal within noise, since the Linux adapter reads every field either way and the wait stops probing after one read there. The macOS speed-up is expected but not yet measured.
