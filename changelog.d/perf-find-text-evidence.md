### Performance

* `find --text`, `--has` and `--has-not` with `--first`, `--last` or `--nth` read actions and states only at the window root, not on every node. A root match is still published from the one window read, and a deeper match is re-read over its own subtree, the same check as before. On macOS, which reads only the fields a query asks for, this should bring `find --text --first` toward the cost of a role-and-name find (it measured 803-1291 ms against 170-350 ms). On Linux, whose adapter reads every field either way, it is unchanged. Each `wait --text` poll after the first reads the window for its text, at the snapshot's own depth, and builds the snapshot only when that read cannot rule the text out. The match is still judged from the snapshot, and a `wait --text --count` polls as before. ([#NNN](https://github.com/gshost1/agent-desktop/pull/NNN))
