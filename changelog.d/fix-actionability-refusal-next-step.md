### Bug Fixes

* A ref action on a target that stays disabled now ends after 2 s with `ACTION_FAILED`, `details.kind: "target_disabled"`, and a suggestion that names the element as disabled. Before, it waited the full 5 s and returned a `TIMEOUT` that called the application busy or unresponsive. Measured on GTK3 and GTK4, it now ends at 2.05-2.21 s instead of 5.02 s. A control the app enables within about 1.6 s is still clicked, and a `--timeout-ms` other than the default waits the whole budget. A headless click, right-click, double-click, triple-click or keyboard input refused because the element has no semantic action now says that `--headed`, when pointer or focus input is acceptable, is the way to act on it, instead of "Waiting will not help". ([#NNN](https://github.com/gshost1/agent-desktop/pull/NNN))
