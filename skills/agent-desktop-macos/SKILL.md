# agent-desktop on macOS

Read the core skill first (`agent-desktop skills get desktop`) for the observe, act, verify loop. This skill covers only what is different on macOS. When a command fails, find the symptom in [references/troubleshooting.md](references/troubleshooting.md).

## Requirements

- macOS 13 or later, Intel or Apple Silicon.
- Accessibility permission for the app that launches agent-desktop (Terminal, iTerm2, Warp, VS Code, Codex). macOS 27 and later name this list Device Control and Data Access. If System Settings lists the `agent-desktop` binary separately, grant it too.
- Screen Recording permission, only for `screenshot` and for `session start --screenshots` artifacts. Window titles do not need it: without it, `list-windows`, `snapshot` and `wait --window` read each title from the window's accessibility element. A title macOS cannot tie to exactly one window is reported as `""`, never as the app name.
- Automation permission for System Events, only where a command reports it missing.

## First contact

1. Run `agent-desktop permissions`.
2. If a permission is denied, run `agent-desktop permissions --guide`. It opens the right System Settings page with a panel that shows the user which app to drag into the list. The user confirms with Touch ID or a password, and the panel moves to the next missing permission by itself. The command returns at once with `"guide": "started"`, `"already_running"` or `"not_needed"`. `agent-desktop permissions --request` shows the system prompts instead.
3. If the guide cannot run, open System Settings > Privacy & Security > Accessibility (Device Control and Data Access on macOS 27 and later). Add the launching app and turn it on.
4. Run `agent-desktop permissions` to confirm `granted`. The next agent-desktop call sees a new grant, so the launching app does not need a restart. Each command reads permissions in its own process, so a permission granted during a `batch` applies from the next CLI call, not to later items in that batch.
5. Run `agent-desktop snapshot -i` to confirm. It reads the focused app. `snapshot --app Finder -i` returns `WINDOW_NOT_FOUND` when Finder has no open window.

`permissions` does not prompt. `permissions --request` can prompt, including for Automation. `permissions --guide` does not prompt and covers Accessibility and Screen Recording only. Automation reports `unknown` when macOS would need to prompt.

## What differs on macOS

**Headed actions.** `click`, `right-click`, `type`, `clear` and `scroll` use physical paths first, except a click on an item in the application's native menu bar hierarchy, which calls `AXPress` without moving the pointer. A headless click on these menu items also calls `AXPress`. Process-owned refs have no window to focus; other ref-target pointer actions focus the exact owning window and verify the hit target before delivery. A headless `right-click` can use `AXShowMenu` when the target provides it. `expand`, `collapse`, `set-value`, `select`, `toggle`, `check`, `uncheck`, `focus` and `scroll-to` stay semantic under `--headed`. `double-click`, `triple-click`, `hover` and `drag` need `--headed`. Raw `--xy` input never changes focus. A headless `click` on an item that publishes `AXOpen` and no `AXPress`, such as a file or folder item, opens it rather than only selecting it. When the item opens in place, the window takes the item's name as its title, which verifies the click, and the old view's refs are gone, so snapshot again. When no effect is seen, the click fails; snapshot before you click again, because the item may already be open.

**In-place edits.** A row being renamed, as after Finder's New Folder, is edited by a separate text editor that floats over the row and holds focus. The editor has no window, so a window snapshot or `find --window-id` does not show it, and the row's own field may be hidden. Get it with `snapshot --app <App> --surface focused -i`: while the edit is open the surface root is the editor, a `textfield` holding the current name. `set-value` or `type` its ref (or the row's field, when the editor provably edits it). The result is `delivered_unverified` with `application_commit: "pending"` and `commit_key: "return"`. Commit with `press return --app <App>`, then check the result independently. Do not press each character with `press`; keys can be dropped.

**File lists and outlines.** Open and Save panel file browsers, and other outlines whose rows rename inline, label each row with an `AXTextField`. That row or cell reports the field's value as `name`, marked `"name_source": "child_field_value"` in snapshots, so `find --surface sheet --name <file>` finds it. A secure field never names a row. The ref still resolves by the row's native address, not by that name.

**Judge delivery by observation.** AX return codes do not prove an effect. Finder returns success from an `AXConfirm` that does nothing. Snapshot again or use `get` and `is` to check the result.

**Surfaces.** Use `--surface menubar` for an app's File, Edit, and View menus. Use `--surface menu-bar-extras` for status items: with no `--app` it reads system items such as Wi-Fi, Battery, and Clock; with `--app` it reads that app's own item. Use `--surface dock` for the Dock. These shell surfaces are available headless through `open-system-surface`. A background app with no ordinary window, such as a menu-bar app or Control Center, can be observed through its process with `snapshot --app "Control Center"`. This applies to `window`, `menubar`, and `menu-bar-extras`, not `focused`; a regular app that has not shown its window returns `WINDOW_NOT_FOUND`. While a menu, sheet, alert, or popover is open, refs from the window tree behind it are the wrong target.
**Menus.** `right-click` headless uses `AXShowMenu`. That call does not return while the menu it opened is tracking, so agent-desktop gives it about 250 ms, then reads the app's menu surface for up to 1.5 s: a menu that opened is a success with a verified step. `ACTION_FAILED` with `details.menu_observed: false` (and `details.perform_budget_ms`) means the app answered but no menu appeared yet; `APP_UNRESPONSIVE` means the app did not answer. Both carry `retry: unsafe`: do not retry, run `wait --menu --app App` or inspect the menu with `--surface menu`. Each fallback step sends nothing unless a menu read answers closed; a read that stays unreadable over a few tries counts as a menu being up. A fallback that selects the row before opening its menu has changed the selection, so if it then fails or no menu appears the result carries `retry: unsafe` (`delivered_unverified`, or `delivery_uncertain` when the menu action itself timed out). `select` opens its menu the same way. `menu` requires an open menu: if `snapshot --surface menu` returns `surface_absent` with `complete: true`, snapshot `menubar` when it exists, click its item without `--headed`, then snapshot `--surface menu`. An absent `menubar` can mean the app exposes no menu bar. A missing `complete`, `complete: false`, timeout or incomplete read is unknown, not absent. For combo boxes and menu buttons, use `select @ref "Option"`. `select` needs a closed-to-open menu transition, so dismiss any open menu first.

**Notification Center.** The notification commands drive Notification Center through accessibility, with the rules in the core `commands-system` reference. When agent-desktop opens the center, it closes it afterwards and restores the previous app focus. Pass both `--expected-app` and `--expected-title` on a single dismiss or action, because the stack shifts. Use `wait --notification --app "App"` for banners that vanish before you list them.

**Long lists in find.** `find` reads the rows of outlines, tables, browsers and lists after everything else in the window or surface. `--first` returns the first match in that order: a match outside list and table rows comes before any match inside them, and find answers it without reading the rows. A control beside a long file list, such as a Save sheet's `Where:` pop-up or its buttons, is found without reading the file list, with an element-token ref. Only when nothing outside the rows matches does `--first` read the rows. A plain `find` and `--count` still read every row, and return `TIMEOUT` when the budget ends inside them; `--allow-partial` returns what they read instead.

**Chromium and Electron.** agent-desktop switches on the web accessibility of a Chromium renderer automatically when it needs it. For a dense running app, use `snapshot --skeleton -i --compact`, then drill with `--root @ref`.

**Identity.** `launch` accepts a display name (`"System Settings"`) or a bundle ID (`com.apple.systempreferences`). Other commands take the display name through `--app`, or the bundle ID or executable name (`ControlCenter`) when no running app has that display name. Window IDs such as `w-4521` stay valid for the life of the window. Find them with `list-windows`.

**Launching a running app.** `launch "App" --activate` on an app that is already running brings it forward through `NSRunningApplication`, not Launch Services, so no reopen event reaches it. It no longer opens a window: an app with none stays windowless (Finder opens no default folder, a document app opens no untitled document) and `data.window` is absent. When you want the app's default or a new window, add `--reopen`; it sends the reopen, and the app opens whatever it opens for one. Do not use `--reopen` just to switch to an app. `data.launch_path` is `attached_running`, `activated_running`, `launched` or `reopened`.

**Launch window and exit.** `launch` claims a window only when the app shows one window, or one focused window among several. An app that restores several windows with none focused returns `ok` with no `data.window` and a `data.suggestion` that lists the window ids once the wait ends (1.5 s after the app finishes starting up, or `--timeout` with `--activate`); pick one with `list-windows`. An app that exits while `launch` waits for its window, before or after it finished starting up and with or without `--activate`, fails with `APP_UNRESPONSIVE` "Launched application exited before it presented a window", `delivered_unverified`, with the pid in `details.pid`.

**Refs use native addresses when available.** A ref turns back into the exact element it was captured from, so identical twins, such as several identical `Delete` buttons, each act on their own row. If the element was removed or the app restarted, the ref is `STALE_REF`, `details.kind: retained_object_stale`, and it never falls back to a search for a look-alike. When an app yields no address for an element, that ref follows the cross-platform rule instead and must have been the only element in its window with its role, native id, name and description. Take a fresh snapshot after a list changes.

**Keys.** The primary modifier is `cmd`: `press cmd+c`, `press cmd+s`. Quit shortcuts such as `cmd+q`, `cmd+shift+q`, `cmd+alt+esc`, `ctrl+cmd+q` and `cmd+shift+delete` return `POLICY_DENIED` unless you pass `--force`. To quit an app, use `close-app`. Punctuation keys work in combos, as the symbol (`,` `.` `/` `;` `'` `[` `]` `\` `-` `=` `` ` ``) or by name (`comma`, `period`, `slash`, `semicolon`, `quote`, `leftbracket`, `rightbracket`, `backslash`, `minus`, `equal`, `grave`). Each one is sent with the key that types it in the active keyboard layout, so `press cmd+,` opens Settings on ANSI and JIS keyboards alike. When the app's focus is in a panel that another process serves, such as a Save sheet, `press --app` sends the keys to that process and skips the app's menu shortcuts; see `references/troubleshooting.md`, Save into a given folder.

**Menu shortcuts.** `press` with `cmd` in the chord and `--app` or `--window-id` first reads the app's menu bar for items whose `AXMenuItemCmdChar`, `AXMenuItemCmdModifiers` and, for named keys such as `delete`, `AXMenuItemCmdVirtualKey` equal the chord. Exactly one enabled match is pressed with `AXPress`, headless included: the step is `AXPress menu shortcut` (`semantic_api`) and `data.details.menu_shortcut` names its `menu` and `item`. AppKit enables window commands such as New Folder or Close Window only while the app is frontmost, so in a background app they read as disabled and do not run. When the only match is disabled and the app is in the background, `press` fails with `ACTION_FAILED`, `details.kind: menu_item_disabled_in_background`, `not_delivered` and safe to retry: rerun it with `--headed`, or `focus-window` first. In every other miss the chord is sent as keys, and `data.details.menu_shortcut.skipped` says why when the lookup applied: `ambiguous` (two enabled items share the chord), `disabled` (frontmost app, only disabled matches), `window_overlay` (the focused window shows a sheet, dialog, alert or popover, which gets the chord before the menu bar does), `menu_open`, `lookup_incomplete` (with `stage`, `kind` and the `menu` where it stopped) or `not_pressable`. The walk has 1 s and 2,048 elements; each submenu read gets 100 ms, and a submenu that misses it is listed in `unread_menus` and skipped. `visited`, `unread_after_budget` and `slowest_read` describe the walk. A read is named `Menu > Item`, with the submenu that holds it in between when there is one, or by its position (`File > item 7`) when the read that returns its title is the one that failed. A keystroke reaches a background app only when it is frontmost, so after a `skipped` result, wait for the effect and fall back to `click` on the menu item. Pressing a menu item can bring the app forward, just as a headless `click` on one can. An unscoped `press` always sends keys.

**Return and Escape on a sheet or dialog.** `press return`, `enter` or `escape` sends a real key first and checks that the sheet's or dialog's own window left the screen. A sheet that only resized has not reacted. A success is `delivered_verified` with `details.modal_key.effect: "observed"`; `effect: "unobservable"` with `delivered_unverified` means the sheet's window could not be told apart, so check the result yourself. When nothing changed it fails with `ACTION_FAILED`, `retry: unsafe` and `effect: "none_observed"`, even though the key was sent. Do not repeat the same press: snapshot the surface with `--surface sheet -i` (a dialog: `--surface alert -i`) and click its default button by ref when `default_button` is `true`. Without one, send the key once more with `--headed` so the window takes focus, or click its Close button to dismiss it. While a panel that another process serves holds the focus, such as a Save panel (`details.keyboard_target.route: "hosted_view"`), this check does not run: the key goes to that process and `keyboard_target.effect` reports the result, with no `modal_key`.

**Cursor overlay.** `cursor-overlay enable` draws the agent cursor in a click-through window. It never moves the OS pointer or activates an app. The macOS motion and image limits are in the core `commands-system` reference.
