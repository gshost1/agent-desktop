### ADAPTERS-1: macOS right-click chain keeps going after an unverified menu and then reports the success as "All chain steps exhausted"

- Pieces:
  - `crates/macos/src/actions/chain/chain_defs.rs:52-84` `RIGHT_CLICK_CHAIN`, `continue_after_unverified_delivery: true`; its doc comment states the invariant "Each step re-checks for an open menu first, so continuing cannot raise a second one".
  - `crates/macos/src/actions/chain/mod.rs:32-51` loop; `:108-117` `record_step_outcome` (returns "keep going" for `DeliveredUnverified` when the flag is set); `:50` `Err(exhaustion_error(..))` when the loop ends.
  - `crates/macos/src/actions/chain/chain_menu_steps.rs:76-97` `show_menu_on_element` (probe, `AXShowMenu`, `wait_for_new_menu`); `:120-131` `wait_for_new_menu` (fixed 600 ms window, 25 ms polls); `:133-141` `menu_probe` = `is_menu_open(..).unwrap_or(false)`; `:50-58` `select_then_show_menu` writes `AXSelected` **before** its own menu probe; `:60-74` `select_then_selected_items_menu` (selects, then `AXShowMenu` or `AXPress` on a "selected items" menu button).
- States today (per chain run): `NoMenu --AXShowMenu ok--> Posted --menu seen <=600ms--> Verified(stop)`; `Posted --not seen--> Unverified(continue)`; each later step: `probe true -> NotDelivered`, `probe false -> mutate again`. End of list with any `Unverified` step and no terminating step -> `Err(ActionFailed "All chain steps exhausted", delivered_unverified)`.
- `menu_probe` collapses a three-state answer (open / closed / probe failed) to `bool` in negative position. Its own comment (`:133-136`) says "a failed probe is the expected shape of 'a menu is up'", yet the failure maps to `false` = "no menu", which is exactly the case where the guard must refuse to mutate again (CONCEPTS "Evidence Tri-State": "fails open the moment it is negated").
- Illegal transitions reachable:
  1. CONFIRMED (traced end to end): headless `right-click` on a control whose `AXShowMenu` opens its menu after more than 600 ms (slow app), or whose app stops answering child reads while it tracks the menu. `show_menu` returns `DeliveredUnverified` (`chain_menu_steps.rs:92-96`) -> chain continues (`mod.rs:42-43`) -> `select_then_show_menu` -> `select_containing_item` writes `AXSelected=true` on the element or an ancestor (`:143-163`) even though the menu is up, then probes and returns `NotDelivered` -> `selected_items_menu` re-selects, probes, `NotDelivered` -> child/ancestor steps probe, `NotDelivered` -> loop ends -> `exhaustion_error` with `delivered_unverified`. The caller gets `ACTION_FAILED` for a right-click whose menu is on screen, plus a selection change it never asked for.
  2. SUSPECTED (needs probe): when the probe fails during menu tracking, every later step sees "no menu" and fires `AXShowMenu` / `AXPress` on another element (selected-items menu button, up to 5 children, 3 ancestors), so a second menu, or a press on a menu button, can be delivered. Needs a probe of whether `is_menu_open` errors (rather than answers true) while an app is in menu tracking.
  - Test sketch (fails on main, macOS test target): in `chain_tests.rs`, build a `ChainDef { steps: [CustomWithDeadline{ret DeliveredUnverified}, CustomWithDeadline{ret NotDelivered} x3], continue_after_unverified_delivery: true }` and run `execute_chain` on `AXUIElementCreateSystemWide()`; assert `Ok(steps)` with the first step `succeeded`. Main returns `Err("All chain steps exhausted")`. A second test: `menu_probe` given an `Err` from the reader must not return "closed" (needs `menu_probe` to take the reader as a parameter, the same seam `verify_menu_opened_with` in open PR #399 uses).
- Hidden cost: 600 ms `wait_for_new_menu` per `AXShowMenu` attempt, up to 1 + 1 + 1 + 5 + 3 = 11 attempts in the worst case, each with a menu probe; measured: none; estimate up to ~6.6 s of polling on an app that answers `AXShowMenu` success without a menu.
- Impact: **B** (wrong error for a delivered action; unrequested selection mutation). A if (2) is confirmed.
- Proposed explicit form: `enum MenuEvidence { Open, Closed, Unknown }` returned by the probe; a chain-level `MenuGuard` state `{ Closed, PostedUnseen, Open, Unknown }` threaded through the right-click steps by one `fn advance(self, MenuEvidence) -> Self`. Steps may mutate only from `Closed`; `PostedUnseen` or `Unknown` at chain end returns `Ok(delivered_unverified)`, not exhaustion. Move the probe ahead of `select_containing_item`. Files: `chain_menu_steps.rs`, `chain_defs.rs`, `chain/mod.rs` (the generic `continue_after_unverified_delivery` end-of-chain rule: an unverified delivery followed only by `NotDelivered` must end as `Ok`). Size M. The end-of-chain rule is a separable small behavior fix (S).
- Overlap: open PR vercel-labs#399 ("right-click --headed reports All chain steps exhausted with the menu on screen") fixes the same symptom only for the headed `CGClick` rung by verifying it with a new-menu wait; the headless `show_menu` path and the probe collapse remain. Same engine flag exists on Windows (`crates/windows/src/actions/chain.rs:106`) but is `false` in every shipped chain (see ADAPTERS-12).
- Prior art: vercel-labs#399 (OPEN, partial, headed only). Searches: "right-click menu", "AXShowMenu", "show_menu", "menu open probe" (issues + PRs); `git log --all -S'menu_probe'` (only 00ffcee3 "let a faulted menu probe cost only the menu", which introduced the swallow).

Unit level (fails on main): `outcome_from_selection(DeliveredUnverified, Some(false))` should not be allowed to continue into a step that is not idempotent; assert that a chain `[press->WithoutEffect, counter step]` never runs a non-selection step (requires tagging steps as idempotent).

- Impact: **A** if confirmed (wrong action delivered).
- Proposed explicit form: split `DeliveredWithoutEffect` into a typed hand-off `PressOutcome::SelectionPending` that only `select_within_container` (idempotent, verified by readback) may consume; `AXOpen`, `activate_descendant` and `AXConfirm` are reachable only from `NotDelivered`. One transition fn on the chain: `fn next_allowed(prev: Outcome, step: StepKind) -> bool` with `StepKind::{Idempotent, Mutating}`. Files: `chain_delivery.rs`, `chain_defs.rs`, `chain/mod.rs`, `press_selection.rs`. Size S-M; behavior fix separable from the refactor.
- Overlap: ADAPTERS-1 (same engine continuation rule). Latency: `container_select.rs` settle constants.
- Prior art: none found that addresses it. vercel-labs#206 (merged, introduced `DeliveredWithoutEffect`, commit 0691eba2), #455 (OPEN, "fall back to AXOpen when a menu item does not take AXPress", menu items only). Searches: "AXPress selection", "activate_descendant", "AXOpen click".

- Illegal transition: CONFIRMED (traced end to end). The selection did change.

- Hidden cost: none.
- Impact: **B** (wrong disposition; the repeated selection is idempotent, so the harm is the false retry-safety claim).
- Proposed explicit form: make the step return type carry delivery: `struct StepResult { outcome: Result<DeliveryOutcome, AdapterError>, posted: bool }` or a `Mutated<T>` wrapper the step must produce after any write, so `after_steps` gets `posted` from the step instead of from the recorded list. Files: `chain/mod.rs`, `chain_step_exec.rs`, `chain_menu_steps.rs`, `chain_value_write.rs` (drops its hand-rolled tracker). Size M; the `select_containing_item` annotation alone is S.

### ADAPTERS-8: drag preflights reserve exactly the nominal time, so an admitted drag can abort with the button down

- Pieces: Windows `crates/windows/src/input/drag.rs:120-142` `preflight_drag` (`PICKUP_TOTAL_MS + duration + drop_delay` vs `remaining`, zero slack), `:43-93` sequence with per-tick `sleep_bounded` (`input/mouse/mod.rs:238-242`: caps the sleep at the remaining time then fails `ensure_remaining`); Linux `crates/linux/src/input/mouse/drag_plan.rs:89-104` same arithmetic, then `x11/worker.rs:163-189` `check_alive` before every step and inside every 10 ms pause slice.
- States: `Preflight(ok) -> PickedUp(armed) -> Moving -> Dropped(disarmed)`; any overshoot of the nominal schedule (per-tick `SendInput`/X request cost, sleep granularity) moves `Moving -> Aborted` with an emergency release at the origin.
- Illegal transition: CONFIRMED by arithmetic, reachable only with a tight budget (`--duration-ms`/`--drop-delay-ms` close to the remaining timeout): preflight passes with `remaining == required`, every tick's overhead accrues, the deadline expires mid-drag, the guard posts a drag-back + button-up at the origin, and the result is `TIMEOUT` + `delivered_unverified`. Test sketch: Windows `drag_tests.rs` with the fake sink and a deadline of exactly `required_ms` plus a sleep shim that overshoots 1 ms per tick; assert either refusal at preflight (`not_delivered`) or completion. Main aborts mid-drag.
- Hidden cost: none extra; the cost is a wasted gesture.
