agent-desktop reads every app through the OS accessibility tree, and that path works for Chromium and Electron apps too. Their web contents can be dense and slow to walk, though. For a browser you can launch fresh, `launch --cdp` starts it with a loopback-only Chrome DevTools Protocol (CDP) port, and the `web` snapshot surface reads the page over that port. Refs from a web snapshot act through the page in the background: the window is not raised and the pointer does not move.

<table>
  <thead>
    <tr><th>Part of the app</th><th>Drive it with</th></tr>
  </thead>
  <tbody>
    <tr><td>The page: links, forms, buttons, text</td><td><code>snapshot --surface web</code> and the usual ref commands</td></tr>
    <tr><td>Native menu bar, file dialogs and sheets, window management, notifications, screenshots</td><td>The accessibility surfaces</td></tr>
    <tr><td>An app that is already running, or one you did not launch</td><td>The accessibility surfaces only. The port exists only on a process launched with it</td></tr>
  </tbody>
</table>

The examples on this page ran against Google Chrome on macOS. Agents read the same loop with `agent-desktop skills get web`.

## 1. Launch the browser with a DevTools port

```bash
agent-desktop launch "Google Chrome" --cdp --arg=--user-data-dir="$PWD/chrome-profile" --arg=--no-first-run --arg=--no-default-browser-check
```

`--cdp` adds the remote-debugging switches, waits until the endpoint answers, checks that the launched process owns it, and returns it in `data.cdp`. Omit the port, as here, to let the OS pick a free one, or pass one (`--cdp 9229`). `--user-data-dir` keeps the session out of the user's profile, and the two `--no-*` switches skip the dialogs a fresh profile opens. On Linux, Chromium joins the accessibility bus only when asked, so add `--env ACCESSIBILITY_ENABLED=1 --arg=--force-renderer-accessibility` to keep the native UI visible; see [Linux](/desktop/platforms/linux#chromium-qt-and-electron).

This is the result, with the window object trimmed:

```json
{
  "version": "2.6",
  "ok": true,
  "command": "launch",
  "data": {
    "app": "Google Chrome",
    "cdp": {
      "http_endpoint": "http://127.0.0.1:62332",
      "port": 62332,
      "product": "Chrome/156.0.8078.80",
      "websocket_url": "ws://127.0.0.1:62332/devtools/browser/7bd6bb05-38fc-480f-9e04-a4acd8aa10f3"
    },
    "suggestion": "Next: read the web content with `snapshot --app \"Google Chrome\" --surface web -i` and act on its refs with the usual commands; `data.channel` is `cdp` when it was read over this endpoint. In a web browser, `open-url <url> --app \"Google Chrome\"` loads a page; an app that embeds web content for its own interface refuses it. Do not hand-roll raw CDP or call app-internal APIs. Native menus, dialogs, windows, and screenshots stay on the accessibility surfaces."
  }
}
```

agent-desktop refuses `--cdp` for an app that is already running, because a running process has no port and quitting it would lose the user's tabs. It finds the running app by the name you pass, so on Linux a launcher alias such as `google-chrome` skips the check and the launch times out instead.

## 2. Load and read the page

```bash
agent-desktop open-url "https://example.com/" --app "Google Chrome"
agent-desktop snapshot --app "Google Chrome" --surface web -i
```

`open-url` returns after the page's load event, with `url`, `title`, `channel`, `target_id` and `opened` (`current_tab`, or `new_tab` with `--new-tab` or when the browser had no page). The snapshot reads the visible tab of the window you name and reports `data.channel`. `cdp` means the page was read over the port. `ax` means no endpoint reached the browser, so the window was read through the accessibility tree; `data.suggestion` names the `launch --cdp` command that enables the web channel.

## 3. Act on the page

```bash
agent-desktop click @s8f3k2p9:e1
agent-desktop snapshot --app "Google Chrome" --surface web -i
```

`click`, `double-click`, `set-value`, `type`, `clear`, `select`, `check`, `uncheck`, `toggle`, `focus`, `scroll` and `scroll-to` work on web refs. Other actions return `ACTION_NOT_SUPPORTED`, and `--headed` is refused. `click` returns once the click is delivered, not when the next page loads, so check `data.url` in the next snapshot. A ref from a page that has since navigated fails with `STALE_REF` and `details.kind: cdp_document_replaced`.

An element the page makes clickable with a script, such as a `<div>` or `<span>` with a click listener and no ARIA role, gets a ref as a `group` that advertises `Click`. When it has no accessible name, its text becomes its `name` with `"name_source": "contained_text"`. An element that holds a link or button gets no ref of its own, and neither does one whose click handler sits only on a parent element.

A click on an element that something else covers is refused before it is sent:

```json
{
  "version": "2.6",
  "ok": false,
  "command": "click",
  "error": {
    "code": "ACTION_FAILED",
    "message": "Another element covers DOM node 32 at the point the click would land",
    "suggestion": "Close the overlay or dialog that covers the element, or scroll it clear, then snapshot again",
    "details": { "backend_node_id": 32, "hit_backend_node_id": 30, "kind": "cdp_click_intercepted", "point": { "x": 600.0, "y": 648.65625 } },
    "disposition": { "delivery": "not_delivered", "retry": "safe" }
  }
}
```

## 4. Keep the native UI on the accessibility surfaces

The window chrome, menus, and dialogs are not part of the page, so read them with a window or surface snapshot in the same run:

```bash
agent-desktop find --app "Google Chrome" --role textfield --first          # the address bar
```

Use `snapshot --surface` for a native file dialog or sheet the page opens; see [Surfaces](/desktop/surfaces).

## 5. Close the browser

```bash
agent-desktop close-app "Google Chrome"
```

`close-app` ends the process and with it the port. While the port is open, any local process of the same user can control the browser's pages, so request `--cdp` only for the task that needs it.

## When `--cdp` fails

<table>
  <thead>
    <tr><th>Error</th><th>Cause</th><th>What to do</th></tr>
  </thead>
  <tbody>
    <tr><td><code>ACTION_FAILED</code>, <code>details.kind: cdp_requires_fresh_launch</code></td><td>The app is already running. <code>details.pids</code> lists it, and nothing was launched (<code>not_delivered</code>).</td><td>Ask before you close it, because the user loses their tabs. Then run <code>close-app</code>, confirm the exit, and launch again with <code>--cdp</code>, or drive the running app through accessibility.</td></tr>
    <tr><td><code>ACTION_FAILED</code>, <code>details.kind: cdp_endpoint_unavailable</code></td><td>The app started, but no DevTools endpoint answered before the deadline. The app keeps running (<code>delivered_unverified</code>).</td><td>Use the accessibility path, or <code>close-app</code> and check the app name and arguments.</td></tr>
    <tr><td><code>INVALID_ARGS</code>, <code>details.kind: cdp_port_in_use</code></td><td>The port you named is bound.</td><td>Name another port, or omit it.</td></tr>
    <tr><td><code>INVALID_ARGS</code>, <code>details.kind: cdp_switch_conflict</code></td><td>An <code>--arg</code> sets <code>--remote-debugging-*</code> or <code>--remote-allow-origins</code>, which <code>--cdp</code> owns.</td><td>Drop that <code>--arg</code>.</td></tr>
  </tbody>
</table>

The flags are in the [`launch` reference](/desktop/commands/app-window#launch). For a dense app you cannot relaunch, map it with a skeleton and drill into one region instead; see [Skeleton and drill-down](/desktop/skeleton-and-drill-down).
