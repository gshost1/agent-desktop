These commands drive the OS notification surface: Notification Center on macOS, Action Center on Windows, and the GNOME Shell message list on Linux. Command names, arguments, and JSON fields are the same everywhere. Titles and bodies are returned verbatim and are not redacted, so treat them as sensitive.

- **Listing** is read-only. Linux lists without `--headed`, even when the list is closed. On macOS and Windows a headless call works only while the surface is already open; otherwise it returns `POLICY_DENIED`, and `--headed` may open the surface.
- **Mutations** (`dismiss-notification`, `dismiss-all-notifications`, `notification-action`) always need `--headed`, because they open and focus the notification surface.
- **Identity guard.** Notifications reorder between listings, so `dismiss-notification` and `notification-action` take the `key` of the entry from the same `list-notifications` result as `--key`. The key covers the app, title and body, and tells identical twins apart. If the entry at `INDEX` no longer carries the key, or no entry does, nothing is pressed and the command returns `NOTIFICATION_NOT_FOUND`. `--expected-app` or `--expected-title` instead of `--key` still works, but checks only those fields, so a newer notification with the same app and title at `INDEX` passes.

To block until a new notification arrives, use [`wait --notification`](/desktop/commands/wait#notification). The JSON examples on this page are built from the command code and tests; notifications could not be exercised in the Linux session the other examples came from, which had no notification service:

```json
{
  "code": "PLATFORM_NOT_SUPPORTED",
  "message": "No notification service is running in this session",
  "details": { "daemon": "absent", "detail": "no service owns org.freedesktop.Notifications" }
}
```

## list-notifications

Lists the notifications on the OS surface.

```bash
agent-desktop list-notifications [--app NAME] [--text TEXT] [--limit N]
```

<table>
  <thead>
    <tr><th>Flag</th><th>Default</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td><code>--app NAME</code></td><td>all apps</td><td>Only notifications from this app, ignoring case.</td></tr>
    <tr><td><code>--text TEXT</code></td><td>none</td><td>Only notifications that contain this text.</td></tr>
    <tr><td><code>--limit N</code></td><td>no limit</td><td>Maximum number returned.</td></tr>
  </tbody>
</table>

```json
{
  "version": "2.6",
  "ok": true,
  "command": "list-notifications",
  "data": {
    "count": 1,
    "notifications": [
      { "index": 1, "app_name": "Calendar", "title": "Standup in 10 minutes", "body": "Room 4", "actions": ["Snooze", "Open"], "key": "74622da481283846-1" }
    ]
  }
}
```

`index` is 1-based and counts the unfiltered list, so a filtered result can start above 1. `body` and `actions` are omitted when empty. `key` is opaque and always present: a digest of app, title and body, then `-` and the entry's count among identical entries from the top. Filters do not change it. Errors: `POLICY_DENIED` on macOS or Windows with the surface closed, and `PLATFORM_NOT_SUPPORTED` when there is no notification service (on Linux, an owner other than GNOME Shell).

## dismiss-notification

Dismisses one notification, named by its key.

```bash
agent-desktop --headed dismiss-notification INDEX --key KEY
agent-desktop --headed dismiss-notification --key 74622da481283846-1
agent-desktop --headed dismiss-notification 2 --expected-title "Standup in 10 minutes"
```

<table>
  <thead>
    <tr><th>Flag or argument</th><th>Default</th><th>Meaning</th></tr>
  </thead>
  <tbody>
    <tr><td><code>INDEX</code></td><td>required without <code>--key</code></td><td>1-based index from <code>list-notifications</code>. With <code>--key</code>, the keyed entry must still be at <code>INDEX</code>.</td></tr>
    <tr><td><code>--key KEY</code></td><td>none</td><td>The entry's <code>key</code> from <code>list-notifications</code>. Without <code>INDEX</code>, dismisses that entry wherever it now sits.</td></tr>
    <tr><td><code>--expected-app APP</code>, <code>--expected-title TITLE</code></td><td>one, without <code>--key</code></td><td>The app or title the notification must have.</td></tr>
    <tr><td><code>--app NAME</code></td><td>none</td><td>Require the notification to come from this app.</td></tr>
  </tbody>
</table>

`data.dismissed` is the removed notification, in the `list-notifications` row shape. Errors: `INVALID_ARGS` without `--key` and without an `--expected-*` flag beside `INDEX`, or for a malformed key; `POLICY_DENIED` without `--headed`; and `NOTIFICATION_NOT_FOUND` (`not_delivered`) when the key is gone or the entry no longer matches.

## dismiss-all-notifications

Dismisses every notification, or every one from one app.

```bash
agent-desktop --headed dismiss-all-notifications [--app NAME]
```

`data.dismissed_count` counts the removed notifications. When some could not be closed, `data.failures` and `data.failed_count` are added.

## notification-action

Presses a named action button on a notification.

```bash
agent-desktop --headed notification-action INDEX ACTION --key KEY
```

`INDEX` is required, and with `--key` the keyed entry must still be at `INDEX`; `--expected-app` or `--expected-title` instead of `--key` work as for `dismiss-notification`. `ACTION` is a name from the notification's `actions`. The result is an action report, usually `delivered_unverified`: check the effect in the app. Errors: as for `dismiss-notification`, plus `ACTION_NOT_SUPPORTED` when the notification has no button with that name.

Platform limits: GNOME Shell only on Linux, with mutations on X11; see [macOS](/desktop/platforms/macos), [Windows](/desktop/platforms/windows), and [Linux](/desktop/platforms/linux).
